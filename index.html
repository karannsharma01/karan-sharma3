Selected work

Dripi · Production · 2026

Virtual Try-On / Try-Off pipeline

Problem
Generating try-on images needs a heavy diffusion model, but the available GPU had only 16GB of VRAM.
Approach
Built a FLUX pipeline where YOLO detects garments across 66 classes and drives dynamic prompts. Used strict CPU offloading and parallel execution to stay inside the memory limit.
Result
Stable generation within 16GB, with 8 seconds less latency per image.

FLUX · YOLO · PyTorch · Docker

Dripi · Production · 2026

Wardrobe valuation API

Problem
A vision-language service was timing out (HTTP 504) and crashing on GPU out-of-memory errors under load.
Approach
Containerized an async Qwen2-VL API with Docker, added application-level semaphores to cap concurrent GPU work, and applied 4-bit quantization.
Result
Timeouts and OOM crashes eliminated in production.

Qwen2-VL · FastAPI · Docker · Quantization

How I work

Find the real bottleneck first.

A timeout, an out-of-memory crash and a slow response each have different causes. I trace the failure before touching the model.

Decide the metric up front.

VRAM, latency, error rate, PSNR, SSIM. Every change has to move a number.

Deployed is the definition of done.

Containers, async serving, CI/CD and concurrency limits that hold under real traffic.

Keep learning in the loop.

Papers, research internships and steady problem solving keep my fundamentals sharp.
